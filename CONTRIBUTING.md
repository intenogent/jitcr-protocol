# Contributing to JITCR Protocol

JITCR Protocol is licensed under the Apache License 2.0 and open for contributions.
Feedback, bug reports, documentation fixes, new skills, and pull requests are all
welcome — this is a young project and outside input is genuinely valuable.

---

## Ways to Contribute

**Try it and report friction.**
The most valuable contribution right now is honest feedback — setup issues, unclear
docs, commands that didn't behave as expected, or anything that made you stop and
wonder "wait, what do I do here?" Open a GitHub issue even if you don't have a fix.

**Improve documentation.**
README and HOWTO clarity, typo fixes, better examples, clearer explanations.

**Contribute a skill or template.**
If you build a useful skill, input template, output template, or interaction template
for your own project, consider sharing it. See [HOWTO.md](HOWTO.md) for the skill
format and folder structure.

**Submit a bug fix or protocol change.**
Pull requests against any repo file are welcome. For larger changes — new commands,
changes to core protocol files, new validation modes — open an issue first to discuss
the approach before investing time in a full PR.

---

## How to Submit a Pull Request

1. **Fork the repo** — click Fork on GitHub to create your own copy.
2. **Create a branch** — make your changes on a named branch, not directly on main.
3. **Make focused changes** — one logical change per PR makes review faster and easier.
4. **Sign your commits** — add `-s` to every `git commit` command (see Contributor Sign-Off below). Every commit in your branch needs the sign-off line before you open the PR.
5. **Open the PR** — describe what changed and why. Reference the issue number if one exists.

Nothing changes in the repo without the maintainer's explicit review and approval.

## Contributor Sign-Off

All commits must include a sign-off line. This is a one-flag step — no form, no
separate agreement, no waiting period.

**How to do it:** Add `-s` to your commit command:

```
git commit -s -m "your commit message"
```

Git automatically appends this to your commit message:

```
Signed-off-by: Your Name <you@example.com>
```

By including this line you certify that:

1. The contribution is your own original work, or you otherwise have the
   right to submit it under the Apache License 2.0.
2. You understand the contribution is public and that a permanent record
   of it (including your name and email) is retained in the project history.

**Why it matters:** Under Apache 2.0, contributions are automatically licensed
under the same terms you received — no copyright assignment required. The sign-off
line creates a permanent, traceable record in git history confirming each contributor
certified their work was original and properly licensed. One flag on a commit command.
Clean audit trail for the lifetime of the project.

## Reporting Issues

Open a GitHub issue and include:

- What you expected to happen
- What actually happened
- Your OS and which AI client you're using JITCR with
- Relevant excerpts from your session output, with any sensitive paths redacted
